# 혼잡도 단계와 신뢰도 기준 (crowding-levels)

이 문서는 **숫자를 어떻게 등급으로 바꾸는지**, 그리고 **그 등급을 얼마나 믿을 수 있는지**를 정의합니다.
데이터·기능 담당(계산)과 화면 담당(표시)이 **같은 기준**을 쓰도록 하는 것이 목적입니다. 한쪽만 바꾸면 안 됩니다.

---

## 1. 기준이 되는 숫자: 혼잡도 %

모든 계산의 입력은 **정원 대비 승차 인원 비율(%)** 하나입니다.

> 한 칸 정원 **160명 = 100%**
> 좌석 54석이 꽉 차고 입석이 0명 = **약 34%**

이 척도는 서울교통공사 CSV와 TMAP 퍼즐 API가 **동일하게** 사용합니다 (`docs/api-validation.md` 4번·6번). 그래서 두 소스를 섞어도 변환이 필요 없습니다.

**중요:** 100%는 "꽉 참"이 아니라 "정원"입니다. 출퇴근 시간대에 150%를 넘는 것은 정상입니다. 상한을 100%로 자르면 안 됩니다.

### 서울교통공사 공식 4단계

| 공식 등급 | 범위 | 공식 설명 |
|---|---|---|
| 여유 | ~80% | 여유로운 이동 가능 |
| 보통 | 80~130% | 여유로운 이동 가능 |
| 주의 | 130~150% | 이동 시 불편 |
| 혼잡 | 150%~ | 열차 내 이동 불가능 |

---

## 2. HellStation 5단계

공식 4단계를 그대로 쓰면 "여유"가 너무 넓어서(0~80%) 앉을 수 있는지 없는지가 구분되지 않습니다. HellStation은 **사용자가 실제로 겪는 경험**을 기준으로 5단계로 나눕니다.

| 단계 | 혼잡도 % | 몸으로 느끼는 상태 | 공식 등급 대응 |
|---|---|---|---|
| `EASY` | **0 ~ 45%** | 앉을 자리가 있거나, 서더라도 널널함 | 여유 |
| `BUSY` | **45 ~ 80%** | 앉기는 어렵지만 서서 편히 감 | 여유 |
| `BAD` | **80 ~ 130%** | 사람과 닿음. 이동은 가능 | 보통 |
| `HELL` | **130 ~ 170%** | 몸이 끼임. 내리기 어려움 | 주의 + 혼잡 |
| `WTF` | **170% ~** | 이 열차는 보내는 게 낫습니다 | 혼잡 |
| `UNKNOWN` | — | 데이터 없음 | — |

### 경계값 처리 규칙

경계는 **아래를 포함하고 위를 제외**합니다 (`[하한, 상한)`).

- `45.0%` → `BUSY` (`EASY` 아님)
- `80.0%` → `BAD`
- `130.0%` → `HELL`
- `170.0%` → `WTF`

경계에서 등급이 왔다 갔다 하며 화면이 깜빡이는 것을 막기 위해, **표시할 때는 이력 현상(hysteresis)을 겁니다**: 이미 표시 중인 등급에서 벗어나려면 경계를 **5%p 이상** 넘어야 합니다. 예) 현재 `BAD`(80~130)를 표시 중이면 `129.9% → 131%`가 되어도 유지하고, `135%`가 되어야 `HELL`로 바뀝니다.

### 왜 45%인가

좌석 만석이 34%입니다. 45%면 좌석이 다 차고 입석이 칸당 약 18명 — "빈자리를 찾아볼 만한가"의 실질적인 경계선입니다.

### 왜 170%인가

공식 "혼잡"은 150%부터지만, 출퇴근 시간대 주요 구간은 150%를 일상적으로 넘습니다. 150%에서 최고 등급을 주면 **출근길 내내 화면이 전부 최고 등급**이 되어 정보 가치가 사라집니다. 170%를 "정말 보내야 하는 수준"으로 남겨 둡니다.

### UNKNOWN을 반드시 만드는 이유

`docs/api-validation.md` 8번에 적힌 대로, 서울시계 밖 역은 실시간 데이터가 없고, 서울교통공사 CSV는 1~8호선만 덮습니다. **9호선·신분당선·공항철도 등은 통계 기준선조차 없습니다.**

이런 역을 `EASY`(초록)로 칠하면 사용자에게 거짓말을 하는 것입니다. 데이터가 없으면 반드시 `UNKNOWN`(회색)으로 두고, "데이터 없음"이라고 적으세요.

## 3. 신뢰도 3단계

같은 "HELL"이라도 **지금 측정한 HELL**과 **작년 통계 평균 HELL**은 전혀 다릅니다. 신뢰도는 이 차이를 사용자에게 알려줍니다.

| 신뢰도 | 무엇을 근거로 계산했나 | 화면에서 |
|---|---|---|
| `HIGH` | 실시간 도착정보가 있고, 데이터 나이 **90초 이내**, 해당 역·방향의 통계 기준선도 존재 | 그대로 표시 |
| `MEDIUM` | 실시간 데이터가 있으나 오래됨(90초~5분)이거나, 통계 기준선만 있고 실시간은 없음 | 값 옆에 "예상" 표시 |
| `LOW` | 인접 역에서 추정했거나, 요일·시간대 평균만으로 채운 값 | "참고용" 안내 문구 필수 |

### 판정 규칙 (순서대로 검사, 먼저 맞는 것 채택)

```
데이터 나이(dataAgeSeconds) = now - recptnDt
```

1. 실시간 도착정보 없음 **그리고** 통계 기준선 없음 → 등급 `UNKNOWN`, 신뢰도 표시 안 함
2. 실시간 없음, 통계 기준선만 있음 → `MEDIUM`
3. 실시간 있음, `dataAgeSeconds > 300` (5분 초과) → `LOW` — 너무 오래됐습니다
4. 실시간 있음, `dataAgeSeconds > 90` → `MEDIUM`
5. 실시간 있음, `dataAgeSeconds <= 90`, 통계 기준선 있음 → `HIGH`
6. 실시간 있음, `dataAgeSeconds <= 90`, 통계 기준선 없음 → `MEDIUM` — 비교 대상이 없어 이상치를 걸러낼 수 없습니다
7. 인접 역에서 추정한 값 → 위 결과가 무엇이든 **`LOW`로 강등**

### 자동 강등

아래 상황에서는 계산 결과와 무관하게 신뢰도를 한 단계 낮춥니다.

- 열차 운행 지연·사고 안내가 감지된 경우 (통계가 무의미해짐)
- 첫차 전 / 막차 후 (`05:30` 이전, `24:30` 이후) — 통계 기준선 자체가 없는 시간대
- 급행(`btrainSttus == "급행"`) 열차인데 통계 기준선이 일반 열차 기준인 경우

## 4. 화면 담당에게 (표시 규칙)

색상 값 자체는 화면 담당이 정합니다. 여기서는 **지켜야 할 제약**만 적습니다.

### 반드시 지킬 것

1. **색만으로 등급을 구분하지 마세요.** 색각 이상 사용자와 흑백 환경을 위해 색 + 아이콘(또는 텍스트 라벨)을 함께 씁니다.
2. **다크 모드에서 5단계가 모두 구분되어야 합니다.** 라이트/다크 각각에서 인접 등급끼리 명도 차이를 충분히 두세요.
3. **`UNKNOWN`은 절대 등급 색상 계열을 쓰지 마세요.** 무채색 회색이어야 "데이터가 없다"가 전달됩니다.
4. **신뢰도가 `LOW`이면 숫자를 크게 표시하지 마세요.** 정확해 보이는 숫자는 신뢰를 과장합니다. `LOW`에서는 등급만 보여주고 % 숫자는 숨기거나 작게 처리하세요.
5. **혼잡도 %를 100%로 자르지 마세요.** 게이지·막대를 그린다면 최대치를 200%로 잡으세요.

### 등급 순서

`EASY → BUSY → BAD → HELL → WTF` 는 **나빠지는 순서**입니다. 색상도 이 순서대로 단조롭게 진해지거나 뜨거워져야 합니다. 중간에 밝기가 튀면 사용자가 순서를 읽지 못합니다.

### 문구 톤

HellStation은 장난스러운 앱이지만, **`UNKNOWN`과 신뢰도 `LOW`, 그리고 운행 장애 상황에서는 장난을 치지 않습니다.** 이때는 담백한 안내 문구를 씁니다. 정보가 없을 때 농담을 하면 사용자는 앱이 고장 났다고 생각합니다.

---

## 5. 데이터·기능 담당에게 (계산 규칙)

### 등급 판정은 한 곳에서만

등급 경계와 신뢰도 판정은 **`CrowdLevel`과 `Confidence`를 만드는 단 하나의 함수**에만 존재해야 합니다. 화면 코드에서 `if (percent > 130)` 같은 비교를 다시 하면 두 기준이 갈라집니다.

### 절대 하면 안 되는 것

- 데이터가 없을 때 `EASY`나 `0%`를 기본값으로 넣기 → 반드시 `UNKNOWN`
- 통계값과 실시간값을 섞은 뒤 신뢰도를 `HIGH`로 올리기 → 낮은 쪽을 따릅니다
- `barvlDt == 0`을 "0초 후 도착"으로 해석 → `docs/api-validation.md` 1번 함정 참고

### 통계 기준선 조회 키

서울교통공사 CSV에서 값을 찾을 때 필요한 키는 다음과 같습니다.

```
(요일구분, 호선, 역번호, 상하구분, 30분 단위 시간대)
```

`요일구분`은 `평일` / `토요일` / `일요일` 세 가지뿐입니다. **공휴일 데이터는 없습니다.** 공휴일에는 `일요일` 값을 쓰되 신뢰도를 `LOW`로 강등하세요.
