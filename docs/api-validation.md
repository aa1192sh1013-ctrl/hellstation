## 1. 실시간 지하철 도착정보 — **AVAILABLE**

가장 중요한 소스입니다. HellStation의 "지금 탈까 기다릴까"는 이 API 위에 세워집니다.

```
GET http://swopenapi.seoul.go.kr/api/subway/{KEY}/json/realtimeStationArrival/{start}/{end}/{역명}
```

- `{역명}`은 URL 인코딩된 한글 (예: `서울` → `%EC%84%9C%EC%9A%B8`). **"역" 글자는 붙이지 않습니다** (`서울역` ❌ / `서울` ✅).
- `{start}`/`{end}`는 0부터 시작해도 동작합니다. `end - start <= 1000`.
- **HTTPS 미지원.** `https://`로 호출하면 연결이 끊깁니다 (2026-08-22 확인). → 앱에서 cleartext 허용 필요, 아래 "앱 설정에 미치는 영향" 참고.

### 실제 응답 (2026-08-22, sample 키, 서울역)

```json
{
  "errorMessage": { "status": 200, "code": "INFO-000", "message": "정상 처리되었습니다.", "total": 22 },
  "realtimeArrivalList": [
    {
      "subwayId": "1001",
      "updnLine": "상행",
      "trainLineNm": "양주행 - 시청방면",
      "statnFid": "1001000134",
      "statnTid": "1001000132",
      "statnId": "1001000133",
      "statnNm": "서울",
      "trnsitCo": "4",
      "ordkey": "01000양주0",
      "subwayList": "1001,1004,1063,1065",
      "statnList": "1001000133,1004000426,1063080313,1065006501",
      "btrainSttus": "일반",
      "barvlDt": "0",
      "btrainNo": "0064",
      "bstatnId": "1001000107",
      "bstatnNm": "양주",
      "recptnDt": "2026-08-22 11:35:50",
      "arvlMsg2": "서울 도착",
      "arvlMsg3": "서울",
      "arvlCd": "1",
      "lstcarAt": "0"
    }
  ]
}
```

### 필드 해석 (직접 확인한 값 기준)

| 필드 | 의미 | 주의점 |
|---|---|---|
| `subwayId` | 호선 코드 (1001=1호선 … 아래 표) | 문자열. 숫자로 변환하지 말 것 |
| `statnId` | 역 고유 ID (`호선 4자리 + 역번호 6자리`) | `1001000133` = 1호선 서울역 |
| `statnFid` / `statnTid` | 이전 역 / 다음 역 ID | **구간(Segment) 구성의 핵심.** 이 두 필드로 노선 그래프를 이어붙일 수 있음 |
| `statnNm` | 역명 | "역" 접미사 없음 |
| `updnLine` | `상행` / `하행` (2호선은 `내선` / `외선`) | 문자열이라 파싱 필요 |
| `trainLineNm` | `"{종착역}행 - {다음역}방면"` | 사람에게 보여줄 문구로 쓰기 좋음 |
| `btrainSttus` | `일반` / `급행` / `ITX` / `특급` 등 | 급행은 혼잡도가 크게 다름 → 반드시 구분 |
| `barvlDt` | **도착까지 남은 초** | `"0"`이 자주 나옴 → 아래 함정 참고 |
| `btrainNo` | 열차 번호 | 같은 열차를 여러 역에서 추적하는 키 |
| `bstatnNm` / `bstatnId` | 종착역 | |
| `arvlCd` | `0`진입 `1`도착 `2`출발 `3`전역출발 `4`전역진입 `5`전역도착 `99`운행중 | `barvlDt`보다 신뢰도 높음 |
| `arvlMsg2` | `"3분 후 (시청)"`, `"서울 도착"` 같은 표시 문구 | 그대로 화면에 쓸 수 있음 |
| `recptnDt` | **데이터 생성 시각** | 지금 시각과 차이가 남. 반드시 보정할 것 |
| `lstcarAt` | 막차 여부 (`1`=막차) | |
| `trnsitCo` | 환승 노선 수 | |

### 반드시 알아야 할 함정

1. **`barvlDt`가 `"0"`으로 오는 경우가 매우 잦습니다.** 위 실제 호출에서도 상당수가 `"0"`이었습니다. `barvlDt`만 믿고 "0초 후 도착"으로 표시하면 틀립니다. → `arvlCd` + `arvlMsg2`를 함께 보고, `barvlDt == 0 && arvlCd == 99`이면 "정보 없음"으로 처리하세요.
2. **`recptnDt` 지연 보정이 필수.** 같은 응답 안에서도 항목마다 `recptnDt`가 제각각이었습니다 (`11:31:29` vs `11:35:50`, 최대 4분 차이). 실제 남은 시간 = `barvlDt - (now - recptnDt)`.
3. **환승역은 한 번의 호출로 여러 호선이 섞여 옵니다.** 서울역 요청에 1호선(1001), 4호선(1004), 경의중앙선(1063), 공항철도(1065)가 모두 포함됐습니다. 호선 필터링은 클라이언트 몫입니다.
4. **sample 키로는 서울역만 조회됩니다.** 다른 역을 붙이려면 실시간 전용 인증키가 필요합니다.

### 호선 코드 (`subwayId`)

| 코드 | 호선 | 코드 | 호선 |
|---|---|---|---|
| 1001 | 1호선 | 1063 | 경의중앙선 |
| 1002 | 2호선 | 1065 | 공항철도 |
| 1003 | 3호선 | 1067 | 경춘선 |
| 1004 | 4호선 | 1071 | 수인분당선 |
| 1005 | 5호선 | 1075 | 신분당선 |
| 1006 | 6호선 | 1077 | 신림선 |
| 1007 | 7호선 | 1092 | 우이신설선 |
| 1008 | 8호선 | 1093 | 서해선 |
| 1009 | 9호선 | 1081 | 경강선 |

> 1001·1004·1063·1065는 이번 호출에서 직접 확인했습니다. 나머지는 실제 키를 받은 뒤 한 번 검증하고 `docs/data-model.md`의 `LineId`와 대조하세요.

## 2. 지하철역 좌표 `subwayStationMaster` — **AVAILABLE**

Heatmap 화면이 역을 어디에 찍을지 결정하는 소스입니다.

```
GET http://openapi.seoul.go.kr:8088/{KEY}/json/subwayStationMaster/{start}/{end}/
```

### 실제 응답 (2026-08-22, sample 키)

```json
{"subwayStationMaster":{"list_total_count":784,
 "RESULT":{"CODE":"INFO-000","MESSAGE":"정상 처리되었습니다"},
 "row":[
   {"BLDN_ID":"0150","BLDN_NM":"서울역","ROUTE":"1호선","LAT":"37.556228","LOT":"126.972135"},
   {"BLDN_ID":"0151","BLDN_NM":"시청",  "ROUTE":"1호선","LAT":"37.565715","LOT":"126.977088"}
 ]}}
```

- **총 784건** — 전체를 한 번 받아 앱에 캐싱하는 것을 권장합니다 (매번 호출할 이유가 없습니다).
- `LAT` / `LOT`가 **문자열**입니다. `LOT`은 오타가 아니라 실제 필드명입니다 (longitude).
- 여기 역명은 `"서울역"`인데 1번 API의 역명은 `"서울"`입니다. **접미사 "역"이 붙고 안 붙고가 소스마다 다릅니다.** 역명 정규화가 필요한 이유입니다.
- `BLDN_ID`(`0150`)는 1번 API의 `statnId`(`1001000133`)와 **체계가 다릅니다.** 조인 키는 `BLDN_NM`(역명) + `ROUTE`(호선)입니다.
- 페이지당 최대 1000건이므로 `1/1000`으로 한 번에 받을 수 있습니다.

## 3. 노선별 역 정보 `SearchSTNBySubwayLineInfo` — **AVAILABLE**

```
GET http://openapi.seoul.go.kr:8088/{KEY}/json/SearchSTNBySubwayLineInfo/{start}/{end}/
```

### 실제 응답 (2026-08-22, sample 키)

```json
{"SearchSTNBySubwayLineInfo":{"list_total_count":799,
 "row":[
   {"STATION_CD":"1707","STATION_NM":"명학","STATION_NM_ENG":"Myeonghak",
    "LINE_NUM":"01호선","FR_CODE":"P148","STATION_NM_CHN":"鸣鹤","STATION_NM_JPN":"ミョンハク"}
 ]}}
```

- **총 799건.** 2번(784건)과 건수가 다릅니다 → 두 소스를 합칠 때 누락되는 역이 생깁니다. 역명 기준 outer join 후, 좌표가 없는 역은 지도에 찍을 수 없으므로 별도 처리하세요.
- `LINE_NUM`이 `"01호선"` 형식입니다. 1번 API의 `subwayId`(`"1001"`), 4번 CSV의 `호선`(`1`)과 **모두 형식이 다릅니다.** 노선 식별자 정규화가 반드시 필요합니다 (→ `docs/data-model.md`의 `LineId`).
- `FR_CODE`는 역 외부 표기 코드(`P148`, `151`)로, 역 안내판에서 사용자가 보는 번호입니다.

## 4. 서울교통공사 지하철혼잡도정보 (CSV) — **AVAILABLE** (파일, API 아님)

실시간 혼잡도 API가 없기 때문에 **HellStation 혼잡도의 기준선(baseline)은 이 파일입니다.** 앱에 동봉해서 오프라인으로 씁니다.

- 받는 곳: 공공데이터포털 `서울교통공사_지하철혼잡도정보` / 서울 열린데이터광장 `OA-12928`
- 형식: **CSV**, 로그인 없이 다운로드, 이용허락범위 제한 없음
- 갱신: **분기 1회** (최신 기준일 2026-03-31)
- 범위: **서울교통공사 1~8호선만.** 9호선·경의중앙선·신분당선·공항철도 등은 **없습니다.**

### 컬럼 구조 (총 48열)

```
요일구분, 호선, 역번호, 출발역, 상하구분, 5시30분, 6시00분, 6시30분, ... , 24시00분, 24시30분
```

- `요일구분`: `평일` / `토요일` / `일요일`
- `상하구분`: `상선` / `하선` (2호선은 `내선` / `외선`)
- 시간대 컬럼: **30분 단위**, 05:30 ~ 24:30
- 값: 해당 30분 동안 그 역을 지나간 열차들의 **평균 혼잡도 %**

### 혼잡도 % 의 정확한 정의 (매우 중요)

> 한 칸 정원 **160명 = 100%**. 좌석(54석)이 꽉 차고 입석이 0명이면 **약 34%**.

즉 **34% 미만이면 앉을 자리가 남아있다**는 뜻이고, **100%를 넘어도 물리적으로 탑승은 가능**합니다. 이 정의를 모르면 혼잡도 단계 기준을 완전히 잘못 잡게 됩니다. → `docs/crowding-levels.md`

### 이 파일의 한계

- 분기 평균이라 **오늘의 사고·지연·행사·날씨를 전혀 반영하지 못합니다.**
- 그래서 이 값만 쓸 때 신뢰도는 항상 `MEDIUM` 이하입니다. → `docs/crowding-levels.md`

## 5. 실시간 열차 위치정보 `realtimePosition` — **PARTIAL**

```
GET http://swopenapi.seoul.go.kr/api/subway/{KEY}/json/realtimePosition/{start}/{end}/{호선명}
```

### 검증 결과

sample 키로 여러 조합(`0/3`, `0/100`, `1/100`, `0/1000`, `1/5` × 1호선/2호선)을 시도했으나 **전부 동일하게 실패**했습니다.

```json
{"status":500,"code":"ERROR-336",
 "message":"데이터요청은 한번에 최대 1000건을 넘을 수 없습니다. ...","total":0}
```

`end - start`가 3인 요청도 같은 에러를 내므로 **에러 메시지가 실제 원인을 가리키지 못하는 상태**입니다. sample 키가 이 엔드포인트를 지원하지 않는 것으로 판단합니다.

→ **응답 구조를 직접 확인하지 못했습니다.** 실시간 전용 인증키를 받은 뒤 다시 검증하고 이 문서를 갱신하세요.

### 왜 필요한가

1번 도착정보는 "역 기준"이라 열차 한 대를 노선 전체에서 추적할 수 없습니다. `realtimePosition`은 "열차 기준"이라 **지연 전파**(앞 열차가 밀리면 뒤 열차도 밀림)를 계산할 수 있습니다. 없어도 앱은 동작하지만, 있으면 예측 품질이 올라갑니다.

**→ 없어도 되는 기능으로 설계하세요.** 이 API에 의존하는 코드는 옵셔널 경로로 분리할 것.

## 6. TMAP 대중교통 퍼즐 혼잡도 — **PARTIAL**

```
GET https://apis.openapi.sk.com/transit/puzzle/subway/congestion/stat/train
GET https://apis.openapi.sk.com/transit/puzzle/subway/congestion/stat/car
Header: appkey: {APP_KEY}
```

### 검증 결과

`appkey` 없이 호출 → **HTTP 401 `{"error":{"id":"401","code":"UNAUTHORIZED"}}`**
엔드포인트는 **살아있고 정상 동작**합니다. 인증만 없는 상태입니다.

실시간 경로로 추정되는 `.../congestion/rltm/car`는 **HTTP 403**으로, 공개되지 않은 것으로 보입니다.

### 파라미터 / 응답 (문서 확인)

| 파라미터 | 필수 | 예시 |
|---|---|---|
| `routeNm` | O | `1호선` |
| `stationNm` | O | `서울역` ← **여기는 "역"을 붙입니다** (1번 API와 반대) |
| `dow` | X | `MON`~`SUN` |
| `hh` | X | `05`~`23` |

응답 주요 필드: `stat[].startStationName / endStationName / prevStationName / updnLine / directAT`, `data[].dow / hh / mm / congestionTrain`, 칸별은 `congestionCar[]` (10칸이면 값 10개), `statStartDate` / `statEndDate`.

- **10분 단위** (4번 CSV의 30분보다 촘촘함), 운행시간 05:30~23:50
- 혼잡도 단위 `%`, **160명/칸 = 100%** → 4번 CSV와 **같은 척도**입니다. 그대로 섞어 써도 됩니다.
- 여전히 **통계값**이지 실시간이 아닙니다 (`statStartDate`~`statEndDate` 기간의 집계).

### 판단

4번 CSV가 무료·무제한이고 척도가 같으므로 **1차 구현에서는 4번만 쓰고 6번은 보류**하는 것을 권장합니다. 6번의 이점은 (a) 10분 단위 정밀도, (b) **칸별** 혼잡도, (c) 1~8호선 밖 노선 커버 가능성입니다. 칸별 기능을 넣기로 결정하면 그때 키를 발급받으세요. 요금 정책은 확인되지 않았습니다.

## 7. 실시간 칸별 혼잡도 — **UNAVAILABLE**

2026년 1월부터 TMAP 대중교통 앱과 또타지하철 앱에서 "실시간 칸별 혼잡도"가 제공되고 있습니다. 서울교통공사 열차 위치 + SKT T-WiFi 데이터 + TMAP 역사 정보를 결합한 것입니다.

## 앱 설정에 미치는 영향 (반드시 읽을 것)

### 1. 인증키 발급 — 사람이 직접 해야 합니다

| 키 | 어디서 | 소요 | 쓰는 API |
|---|---|---|---|
| 서울 열린데이터광장 **일반 인증키** | data.seoul.go.kr → 인증키 신청 | 즉시 | 2번, 3번 |
| 서울 열린데이터광장 **실시간 지하철 전용키** | 나의화면 → 인증키 신청 → **실시간 지하철 인증키 신청** | **1~2일 승인 대기** | 1번, 5번 |
| SK open API `appkey` | openapi.sk.com | 미확인 | 6번 (보류) |

**실시간 전용키는 승인에 1~2일 걸리므로 지금 바로 신청해 두세요.** 없으면 서울역 외 모든 역에서 실시간 도착정보를 붙일 수 없습니다.

### 2. 키를 코드에 넣지 마세요

키는 `local.properties`에 두고 `BuildConfig`로 주입합니다. `local.properties`는 git에 올라가지 않습니다.

```properties
# local.properties (git 추적 안 됨)
SEOUL_OPENAPI_KEY=여기에_일반_인증키
SEOUL_REALTIME_SUBWAY_KEY=여기에_실시간_전용키
```

`app/build.gradle.kts`가 이 값을 읽어 `BuildConfig.SEOUL_OPENAPI_KEY` / `BuildConfig.SEOUL_REALTIME_SUBWAY_KEY`로 만들어 둡니다. 키가 없으면 `"sample"`이 들어가고 **빌드는 그대로 성공**합니다 (키 없이도 개발할 수 있도록).

### 3. HTTP 평문 통신 허용이 필요합니다

서울 열린데이터광장 두 도메인 모두 **HTTPS를 지원하지 않습니다** (직접 확인). Android 9부터 평문 HTTP는 기본 차단이므로 예외 설정이 필요합니다.

지금은 `AndroidManifest.xml`에 `android:usesCleartextTraffic="true"`로 열어 두었습니다. **이건 앱 전체를 여는 거라 안전하지 않습니다.** 해당 도메인만 허용하도록 좁혀야 합니다 — `docs/architecture.md`의 "화면 담당에게 넘기는 일"을 보세요.
